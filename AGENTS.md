# AGENTS.md — usvisa-ca

## Run
- Paid entry: `python3 reschedule.py`. Requires Chrome + repository-root `.env` (see `README.md` vars). `SHOW_GUI=True` hardcoded in `settings.py`.
- Unpaid entry: `python3 payment_tracker.py`. Reads only the payment-page summary and sends Telegram; never pays/books/reschedules. Ignores `TEST_MODE` (real notifications).
- Unpaid alerts: `FIRST_APPOINTMENT_ALERT_IN_RANGE_ONLY="NO"` (default/blank) reports every displayed date regardless of booking window/exclusions; `YES` honors the inclusive window and exclusions. Both modes alert for earlier and later date changes and suppress unchanged dates. Messages use city/date on the first line and `Call +1 (778) 807-9660 to reschedule.` on the second. Validate tracker-only policy at tracker startup, never block paid booking.
- IVRs: `PAID_IVR_ACCOUNT_NUMBER` selects the paid booking group; blank retains first-Continue behavior. Blank/missing `UNPAID_IVR_ACCOUNT_NUMBER` auto-selects only one unambiguous visible dashboard group; multiple groups require the exact unpaid IVR. Never use the paid selector as fallback or select a group explicitly marked paid. Missing tracker/Telegram settings must not block paid booking.
- Dry run: `TEST_MODE="True"` (default) **never clicks confirm** — `legacy_rescheduler.py` raises `UnverifiedReschedule` instead to exercise verification read-only. `False` = live booking.
- No `pytest` installed; use `python3 -m unittest discover -s tests -v`.
- Tests are env-leaky: browser tests read `USER_CONSULATE` from `.env`. Run with `USER_CONSULATE=Calgary` (fakes only offer Toronto 94 / Calgary 89); `ConsulateSettingsTests` pass regardless.

## Architecture
- `reschedule.py`: session lifecycle, polling, verification. `legacy_rescheduler.py`: Selenium calendar/booking only (no `requests`). `settings.py`: `.env` via `python-dotenv`. `request_tracker.py`: retry/time budgets.
- `payment_tracker.py`: exact unpaid-group (or sole dashboard group) Continue → trusted schedule/payment route → heading-scoped summary rows → selected-consulate/optional date filter → initial eligible date and all observed date changes indefinitely. Absence of a booked appointment does not classify payment status.
- Tracker recovery: same-driver transient setup attempts (`NEW_SESSION_AFTER_FAILURES`) and polling failure/time budgets (`DATE_REQUEST_MAX_RETRY` / `DATE_REQUEST_MAX_TIME`, shared `RequestTracker` with injected monotonic clock). Refund complete healthy cycles, including idle/delivery time. Expired/dead drivers, failed restoration, exhausted budgets, and session age renew after `NEW_SESSION_DELAY`; retain alert state and Telegram retry deadlines. Access challenges or 15 consecutive setup/re-establishment failures across drivers close Chrome before one `SOFT_BAN_COOLDOWN` (no extra renewal delay). Reset that streak only on a healthy summary read or cooldown.
- Tracker shutdown: after valid configuration and monitoring startup, `main()` attempts exactly one `Monitoring Stopped` Telegram message after browser cleanup on actual exit (including fatal failure/Ctrl-C/unwinding Python exceptions), never on driver renewal/retries/cooldown. Use the existing bot/chat with bounded connect/read timeouts; delivery/logging failure must not mask the exit outcome, retry, or alter alert state. No sends before monitoring starts, no external watchdog/signal handlers, and no delivery guarantee on force-kill/SIGTERM/power loss/network failure. `TEST_MODE` does not suppress it.
- `telegram_notifier.py`: configuration-independent `send_telegram_message(text, *, bot_token, chat_id, timeout, session)`; one verified HTTPS POST, structured delivery status/retry delay, no sleeps/retries/state/test-mode policy. Caller owns those decisions. Paid-flow Telegram is not yet enabled.
- `.payment_tracker_state.json`: ignored atomic/private version-two state with last healthy observation, last confirmed delivery, and pending flag; scoped by opaque preferences/policy/destination/resolved-IVR-and-schedule fingerprint, rebound on session renewal. Observation changes persist even when filtered/unavailable; confirmed delivery advances only after Telegram success. Reappearing dates alert again, including across restarts. Read/network failures do not change observations. Same-group explicit/automatic selection shares state; version-one files remain readable. One tracker per state file; `--reset-baseline` manually resets tracking.
- Flow: login → dashboard `p.consular-appt` date → appointment page → poll `.../appointment/days/{FACILITY_ID}.json` → `legacy_reschedule()` → success / `False` (retry) / `UnverifiedReschedule`.
- Unverified verify (date-only): fresh login re-reads dashboard (`VERIFY_MAX_READS=3`, `VERIFY_READ_DELAY=10`): `== target` → success+quit; `== previous` repeatedly → silent continue, next session skips one `NEW_SESSION_DELAY`; else manual email+quit. Toggle: `VERIFY_UNVERIFIED_BOOKING="False"` restores old quit-always.
- `reschedule_with_new_session()` returns `(done, skip_delay)`; `__main__` skips the delay once after verified-failure. All Gmail goes through `_send_gmail_notification()` (log-only in `TEST_MODE`).

## Gotchas
- Dates strictly `YYYY-MM-DD`; `USER_CONSULATE` validated case-insensitively against Calgary/Halifax/Montreal/Ottawa/Quebec/Toronto/Vancouver.
- Paid soft-ban: 4× empty date list → `SoftBanDetected` → `SOFT_BAN_COOLDOWN` (1h); 15× setup failures → same. `SessionExpired` (sign_in redirect, 401/403, HTML instead of JSON) must retire the expired driver immediately, never retry reads on it; outer fresh-session delay still applies.
- Tracker navigation: validate route before refresh/extraction; same-group/dashboard drift restores only the saved trusted payment URL. Cross-group/off-site drift abandons the driver without inspecting/refreshing that page. Initial unsafe group/schedule selection remains fatal. Never follow a calendar redirect as successful setup or unavailability.
- Tracker setup routes: exact known blank/new-tab/browser-error pages and an empty current URL are transient throughout setup. Unexpected/malformed login/dashboard routes require a fresh browser and `NEW_SESSION_DELAY`; unsafe group-selection/Continue/payment destinations and schedule mismatches remain terminal. Do not relax HTTPS/exact-authority trust checks or change `reschedule.login()`/paid behavior. Credential-guard changes were excluded.
- Tracker diagnostics: one allowlisted stage/route/error/recovery diagnostic per failed setup attempt or navigation trust failure. Preserve metadata through cleanup but never log arbitrary metadata, hosts, paths, query strings, titles, HTML, tokens, account identities, or exception text. Logs are terminal-only; no log file.
- Tracker transient login/page-load/dashboard timeouts are retryable; positively identified credential rejection, invalid config, ambiguous/paid group selection, corrupt/unwritable state, and permanent Telegram errors remain terminal. Scope broad operational recovery to browser operations only, never alert-state persistence or notification delivery. Fixed recovery messages only, no raw exceptions or URLs. Ctrl-C always closes Chrome/profile, including interrupted cleanup.
- Healthy-but-unusable polls (`forgive_last_retry`) don't consume budget; `MAX_HEALTHY_SESSION_AGE` (90min) forces re-login.
- Never book outside window/exclusions/`ONLY_EARLIER_THAN_CURRENT_APPOINTMENT` guard — the calendar click is untrusted, the post-pick guard in `legacy_reschedule()` is authoritative.
- Never add a same-driver dashboard check that navigates the polling driver away; verification owns its driver and quits it.
- `_find_dashboard_group`/`_get_dashboard_scope` accept an explicit IVR; omitted arguments retain the paid selector and current test monkeypatch behavior. Only an explicitly blank IVR plus `_find_dashboard_group(..., single_group_fallback=True)` permits sole-group selection; discovery must fail closed on malformed/stale cards. Never mutate the paid global to select an unpaid group.
- Tracker unavailable rows are healthy; missing/duplicate/malformed summary data are errors, not empty-calendar soft bans. Recheck dates before delayed sends; never log full HTML, applicant details, tokens, cookies, or credential-bearing exception URLs.
- Current payment DOM selectors need opt-in live validation. Automated tests are offline and local-only; all files under `tests/` are ignored. `legacy/detect_and_notify.py` is superseded.
